# 队头任务钉在忙碌节点时阻塞整个 FIFO（调度缺口，2026-09-07）

- 来源：研究项目 lrd（psibot-hm 头节点，dt 0.13.6；节点 psibot-hm / ds / ys）。
- 现象：用 `dt run --node psibot-hm` 提交的任务排在队头、hm 忙碌时，后面不钉节点的任务不会派发给空闲的 ds；`dt free` 显示 ds `1/1` 空闲、负载 0%，持续十几分钟直到 hm 空出。全局队列是严格 FIFO，只看队头。
- 复现：hm 上有任务运行；依次提交 `dt run --node psibot-hm -- sleep 600` 与 `dt run -- sleep 60`（不钉节点）；观察后者不会到 ds 上运行。
- 影响：为规避 ds 上 OGBench 进程的随机 SIGFPE，本项目必须把这类任务钉到 hm / ys；一旦它们排在队头，ds 就整体闲置。
- 当前规避：把钉节点任务改为 `dt batch <node> -F cmds.txt`（同节点顺序队列），并排在不钉节点任务之后提交；仍会在批任务到达队头时短暂阻塞。
- 建议：调度器对队头不可派发（目标节点忙 / 资源不满足）的任务跳过，继续扫描后续可派发任务（保持同节点内的 FIFO 顺序即可）；或提供 `--exclude-node`，让"除 ds 外任意节点"成为可表达的约束。
