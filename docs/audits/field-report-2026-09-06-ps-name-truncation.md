# `dt ps -a` 截断作业名，按名字去重不可靠（附几处小 UX）

- 报告时间：2026-09-06 01:50 | 来源：RAT-Image 项目代理 | dt 0.13.4 → 0.13.10
- 严重度：低

1. `dt ps -a` 人类输出把 name 截成 `bc240-door-open-500000-s1-001-dt_bc_…`，前缀相同的作业（如 `…-s1` 与 `…-s10`）无法区分；
   我们的去重脚本据此漏判，重复提交过一个已完成的 cell。建议：`--wide` 不截断，或提示用 `dt ps --json` 做程序判断（AGENTS.md 已提到
   `dt_ps_query_v1`，但 `-a` 的人类输出没有提示）。
2. `dt run` 逐个同步派发每次约 4 分钟（2026-09-05 上午实测），文档可在 `dt run` 处直接建议批量场景改用 `dt batch`。
3. `dt pull --to DIR` 在 DIR 非空且无 `dt/job.json` 时拒绝写入（合理），但报错文案没有提示 `--force` 的语义是"合并/覆盖"还是"覆盖"。
